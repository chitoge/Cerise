# Package-index signing keys

Cerise signs dynamic package-index entries with an Ed25519 key. The device
contains only the derived public key; it accepts a dynamic entry only when the
signature verifies. Without a public key, the resolver falls back to the
in-image base index.

The private source tree carries `pkg_index_signing_seed.bin` as a non-production
example. A source tree without it uses the deterministic seed generated by
`//build/keys:dev_signing_seed`. Both are test material: they prove only that
the signing and verification path works and provide no authenticity.

## Supplying a deployment key

Replace the example with a random 32-byte Ed25519 seed supplied by the release
environment before building:

```sh
head -c 32 /dev/urandom > build/keys/pkg_index_signing_seed.bin
```

Never commit or distribute the replacement. A production build should inject
it from a secret store and fail if the expected deployment credential is absent.
Rotating it changes the public key baked into the image, so devices holding the
old key will reject newly signed entries until they receive an image containing
the new public key.

The public key must also be protected by verified boot. Otherwise, an attacker
who can replace the image can replace both a signed entry and the key used to
verify it.
